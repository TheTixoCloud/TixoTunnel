راهنمای ساده راه‌اندازی Backhaul بازنویسی‌شده
ir_spoof — https://t.me/ir_spoof

این نسخه مستقل با Go نوشته شده. هر دو طرف باید همین نسخه را داشته باشند؛
یک طرف را به هسته پریمیوم قدیمی وصل نکن. کلید خصوصی بین دو سرور برای امنیت
خود تونل است؛ ربطی به سایت سازنده یا جمع‌آوری IP ندارد.

۱) نصب روی هر دو سرور

فایل نصب آماده را روی هر دو لینوکس amd64 کپی کن. اول checksum انتشار را
بررسی کن، بعد داخل همان پوشه بزن:

sudo sh backhaul-ir_spoof-linux-amd64-0.1.0.run

Python 3.11 به بالا و systemd لازم است. نصب‌کننده چیزی از سایت سازنده
دانلود نمی‌کند. برای باز کردن دوباره منو:

sudo backhaul-manager

۲) نقش‌ها را مشخص کن

سرور A ورودی کاربران است؛ نقش server دارد.
سرور B جایی است که سرویس اصلی تو اجرا می‌شود؛ نقش client دارد و به A وصل
می‌شود. اسم این نقش‌ها به ایران یا خارج وابسته نیست.

مثال: کاربر به پورت 8080 سرور A وصل می‌شود و ترافیک به پورت 9000 روی
127.0.0.1 سرور B می‌رسد. سرویس مقصد را باید خودت از قبل اجرا کرده باشی.

۳) یک کلید خصوصی مشترک بساز

روی A:

sudo backhaul-manager secret demo --kind token

کلید ساخته می‌شود ولی متنش نمایش داده نمی‌شود. فایل زیر را با روش امنی مثل
SFTP به همان مسیر روی B منتقل کن؛ آن را در کانال یا چت عمومی نفرست:

/etc/backhaul/secrets/demo.token

روی B، قبل از انتقال پوشه را بساز:

sudo install -d -m 700 /etc/backhaul/secrets

بعد از انتقال روی B:

sudo chmod 600 /etc/backhaul/secrets/demo.token

فایل باید در هر دو طرف یکسان باشد؛ روی B یک کلید تازه و متفاوت نساز.

۴) ورودی TCP و UDP را روی A بساز

sudo backhaul-manager create demo --mode server --transport tcp --listen 0.0.0.0:8443 --ports 8080=9000 --accept-udp --secret-file /etc/backhaul/secrets/demo.token --start

این مثال TCP و UDP پورت 8080 را به سرویس هم‌نوع روی پورت 9000 در B می‌برد.
اگر فقط TCP می‌خواهی، گزینه --accept-udp را حذف کن. UDP این حالت داخل تونل
TCP جابه‌جا می‌شود؛ UDP خام اینترنتی نیست.
تنظیم‌های قدیمی ring_size و frame_size و write_timeout_ms در این نسخه
کنترل عملکرد صف یا timeout نیستند؛ رفتار واقعی و محدودیت‌ها در limits آمده.

۵) روی B اتصال را بساز

SERVER_A_IP را با آدرس واقعی و در دسترس سرور A عوض کن:

sudo backhaul-manager create demo --mode client --transport tcp --peer SERVER_A_IP:8443 --secret-file /etc/backhaul/secrets/demo.token --start

پورت ارتباط دو سرور و پورت‌هایی که واقعاً می‌خواهی عمومی باشند را در فایروال
خودت مجاز کن. برنامه فایروال یا NAT کل سرور را خودکار دستکاری نمی‌کند.

۶) وضعیت و مدیریت

sudo backhaul-manager status demo
sudo backhaul-manager stop demo
sudo backhaul-manager start demo
sudo backhaul-manager restart demo

حذف همان تونل و فایل‌های تحت مدیریت خودش:

sudo backhaul-manager delete demo --yes

فعال بودن سرویس به‌تنهایی یعنی مسیر نهایی سالم است؟ نه؛ با کلاینت واقعی
سرویس خودت به A:8080 وصل شو و پاسخ را بررسی کن. سرویس مقصد، فایروال، مسیر
شبکه و یکسان بودن کلید هر دو طرف مهم‌اند.

برای حالت‌های دیگر از منو استفاده کن. TLS با بررسی گواهی روشن است؛ برای
گواهی خصوصی، فایل اعتماد را به کلاینت بده و نام SNI باید با گواهی جور باشد.
کلید، تنظیمات خصوصی و لاگ حاوی اطلاعات سرور را عمومی منتشر نکن.

این بازنویسی معادل بایت‌به‌بایت نسخه اصلی نیست. فرق‌ها در docs/limits.md و
نتیجه تست‌های واقعی در docs/test-report.md آمده است.
